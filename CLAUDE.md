# Cinq

Two-way sync between Roblox Studio scripts and local files. `server/` is the Node app (no dependencies), `plugin/` is the Studio plugin source, and each `Cinq/<PlaceId>/` folder (`Cinq/<file name>/` for unpublished places) in this repo's central `Cinq/` folder is a live mirror of that place's scripts. How to use Cinq (the CLI and working on synced places) is in the global `~/.claude/CLAUDE.md`, so it applies from any project folder; this file only covers developing Cinq itself.

## Developing Cinq
- `npm test` runs the server tests. The port is 34877 (`CINQ_PORT`). `cinq` is linked with `npm link` (undone with `npm unlink -g cinq`). Run global installs like that in the user's Terminal panel (`run_in_terminal`), not Claude's Bash/PowerShell tools: those run inside the Claude app's package, where new folders under AppData are redirected into the package's private `LocalCache`, so the link only exists for Claude.
- Places sync into the places folder: `cinq run <folder>` if given, else `root` in `~/.cinq/config.json` (`CINQ_CONFIG` overrides the path), else this repo's `Cinq/` (`DEFAULT_PLACES_DIR`). `links` in the same file maps a place key (PlaceId, or `0:<file name>`) to its own folder; `resolvePlaceDir` checks links first and `listPlaceDirs` lists both, so every command finds linked places. The server reads links on each connect. `server/config.js` moves folders with the server stopped and refuses targets that already have service folders, since those would merge into Studio.
- The plugin sweeps every synced script's editor source against what it last sent (`Session.sweep`): after `exec`/`edit`, before `wait`'s flush, and every 5+ seconds (longer for big places). In Drafts mode an edit outside an open tab fires no signal, so the sweep is the only way to see it.
- `plugin/Activity.luau` is the Activity dock widget. The server adds `change` (`added`, `removed`, first changed `line`) and `path` to update/create ops, and sends unacknowledged `notice` ops (`PlaceSync.notify`) for conflicts and refused changes, so they don't hold up `cinq wait`. The widget is `PluginGuiService.CinqActivity`, so `exec` can read its rows. It starts empty after every plugin reload, including `install-plugin`.
- Tool output marks synced scripts with `⟦file:<id>⟧`, which the server turns into `→ <file path>` (`linkFiles` in `sync.js`).
- The sourcemap comes from the plugin's `datamodel` tool. Once a place has a `sourcemap.json`, the server rewrites it a few seconds after each script tree change. `check` finds luau-lsp on PATH or in rokit/aftman/foreman, and the Roblox definitions in the Luau VS Code extension's storage (or `--defs`, `CINQ_LUAU_DEFS`).
- In Drafts mode `.Source` is the committed version and `GetEditorSource` the user's draft. `plugin/Drafts.luau` records a draft's base (the committed source when Cinq saw the draft start) in plugin settings `drafts:<place key>` by sync id; `server/drafts.js` classifies and 3-way merges with `merge3`. A base is never guessed, since a wrong one would make a merge revert someone's commit.
- The server refuses (403) any request with an `Origin` header or a non-localhost `Host`, so web pages open in a browser can't run `exec` or other routes. Studio and Node's `fetch` send neither; a new client must not either.
- `cinq install-plugin` builds `plugin/` into `dist/Cinq.rbxm` (for sharing) and `%LOCALAPPDATA%\Roblox\Plugins\Cinq.rbxm`, and Studio hot-reloads it. `--no-install` only builds.
- On Windows `cinq start` creates the server through WMI (`startOutsideJob` in `cli.js`): apps like Claude run their children, detached ones included, in a job they terminate on exit, and a WMI-created process isn't in it. The server logs uncaught errors to `Cinq/.cinq/server.log`, since it has no console.
- One server handles every Studio; a second `cinq run` sees the running one and exits. Studio batches its changes into at most one request every 3 seconds (`EventIntervalSeconds`), so Studio edits can take up to 3 seconds to reach disk. Tool results skip that queue.
- A lost or changed `CinqId` is restored by the plugin, or relinked by the server using the path and then the content. Tagging, untagging or packaging updates live: the files are dropped from or added to disk without touching Studio. `UpdateSourceAsync` always stores LF, which is why Cinq works in LF only.
- Plugin settings remember enabled places as `autoconnect:<PlaceId>`, or `autoconnect:0:<name>` for unpublished places with dots replaced by `_`, since keys with dots don't persist.
- `plugin/` is the source of truth. `cinq install-plugin --mirror plugin` also writes it into the dev place's `ServerScriptService.CinqPlugin`, keeping its `Cinq_Ignore` tag on and removing any Cinq attributes. Never untag that folder to update it: while untagged, Cinq gives its scripts sync ids and editor stamps, and re-tagging doesn't remove them.
